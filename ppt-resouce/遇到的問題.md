# 遇到的問題與處理方式（簡報第 11 頁改寫素材）

本文件整理專題實作過程中**真實遇到且有實際處理**的核心問題，避免過度包裝或與實驗數據矛盾。

---

## 問題一：路面標線（斑馬線、機車待轉區）因透視呈梯形，矩形框易混入背景

- **問題現象**：  
  行車記錄器為前視透視角度，地面的斑馬線與機車待轉區在畫面中多呈現**扁平梯形**；但 YOLOv7 採用水平矩形框（HBB），被迫以矩形去包覆梯形，導致框內混入左右兩側大量柏油路背景，且目標長寬比極端扁平，容易造成 Anchor 匹配失敗或定位偏差。
- **處理方式**：
  1. **標註端統一規範**：全組採用「最小緊貼外接矩形」框住標線四個極端點，遇車輛局部遮蔽仍視為同一完整目標，減少標註雜訊。
  2. **訓練端超參數適配（v1）**：將 **`anchor_t` 由 `4.0` 放寬至 `6.0`**，容許極扁長寬比目標匹配 Anchor；同時**關閉旋轉（`degrees=0`）、剪切（`shear=0`）與透視變形（`perspective=0`）**，避免水平框進一步膨脹失真。

## 問題二：純人工標註耗時高，委託通用 AI Agent 代標卻出現框體漂移、誤標與漏標

- **問題現象**：  
  行車記錄器影片雖可透過抽幀工具快速產出大量影像，但純人工精標 **50 張即需耗時約 1～1.5 小時**；若改請通用 AI Agent 參考人工範例直接代為標註，實測發現容易出現**邊界框位置漂移、類別標錯或漏標**（通用視覺語言模型對精確像素座標回歸較弱，且缺乏台灣特有「機車待轉區」與細分標誌概念）。
- **處理方式與建議解法（Human-in-the-Loop 人機協作）**：
  1. **嚴格人工複檢**：不直接將通用 AI Agent 的輸出送入訓練，改以 X-AnyLabeling 逐張修正，避免錯誤標籤污染模型（Garbage In, Garbage Out）。
  2. **專屬模型預標註（Model-Assisted Pre-labeling）**：先以人工精標的種子資料（如現有 458 張）訓練出**專屬 YOLOv7 模型**（如 Exp 7 / Exp 8），再對新抽幀影像執行推論產生**初始預標註框**，匯入 X-AnyLabeling 後由人工只做**「微調與補漏」**而非從零畫框，可大幅降低漂移並將標註速度提升數倍。
  3. **信心度分流審核**：預標註時保留信心分數，高信心目標快速掃描確認、中低信心目標優先人工複查，將時間集中在模型最不確定的難例上。

## 問題三：YOLOv7（2022）於新版 Colab／Python／套件升級環境下的相容性斷裂

- **問題現象**：  
  YOLOv7 官方程式碼與 `requirements.txt` 撰寫於 2022 年；本專案於 Google Colab 執行期間，Colab 預設環境已陸續升級至 **Python 3.12／3.13、PyTorch 2.6+、NumPy 2.x**，導致原生程式碼在套件安裝、權重載入、mAP 評估與多尺度訓練階段陸續出現相容性錯誤，必須在 `NCHU_Research_YOLOv7.ipynb` 中持續加入對應修補。
- **實際遭遇的升級衝突與調整紀錄**：

| 升級項目／觸發原因 | 實際報錯與影響 | Notebook 對應調整方式 |
| :--- | :--- | :--- |
| **Colab 套件版本更新 vs. 舊版 `requirements.txt`** | 執行 `pip install -r requirements.txt` 時試圖降級新版 NumPy，引發底層重新編譯失敗。 | 放棄整份 `requirements.txt`，改沿用 Colab 預裝的 PyTorch／NumPy／OpenCV，僅補裝缺少的 `thop` 與 `albumentations`。 |
| **PyTorch 2.6+ 預設 `weights_only=True`** | `torch.load()` 安全性升級，導致載入含自訂模型物件的 YOLOv7 `.pt` 權重時拋出 `UnpicklingError`。 | 初期以 monkey-patch 注入 `train.py`／`test.py`／`detect.py` 強制 `weights_only=False`；後期改採官方環境變數 `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1` 統一處理。 |
| **NumPy 2.0+ 移除 `np.trapz`** | NumPy 2.x 將 `np.trapz` 更名為 `np.trapezoid`，造成 `utils/metrics.py` 在計算 AP／mAP 時觸發 `AttributeError`。 | 自動修補 `yolov7/utils/metrics.py`，改為相容寫法 `getattr(np, "trapezoid", getattr(np, "trapz", None))`。 |
| **Python 3.12+ 嚴格檢查 `random.randrange` 型別** | 啟用 `--multi-scale` 訓練（Exp 12／13）時，`train.py` 傳入 `imgsz * 0.5` 等 `float` 參數，觸發 `TypeError`。 | 自動修補 `yolov7/train.py`，將範圍參數顯式轉型為 `int(imgsz * 0.5)` 與 `int(imgsz * 1.5 + gs)`。 |
| **Colab 雲端整合與 YOLOv7 舊版工具鏈相容** | 1. 訓練時 `wandb` 跳出互動登入提示導致非互動執行卡住。<br>2. `utils/google_utils.py` 將路徑強制 `.lower()`，在 Linux／Google Drive 含大寫路徑時誤判權重不存在，轉向 GitHub API 下載又遇限流觸發 `KeyError: 'assets'`。 | 1. 設定 `WANDB_MODE=disabled` 停用互動提示。<br>2. 修補 `google_utils.py` 移除 `.lower()` 並加上 `.get()` 防呆，同時推論前將權重複製至全小寫本地路徑。 |

- **處理方式（可重現性設計）**：  
  不仰賴人工手動修改檔案，而是將上述所有環境變數與程式碼修補集中寫入 `NCHU_Research_YOLOv7.ipynb` 的 **Step 3 環境初始化儲存格**，每次開啟全新 Colab Runtime 時自動執行熱修補（Auto-Patching），確保實驗環境可一鍵重建且結果可重現。
