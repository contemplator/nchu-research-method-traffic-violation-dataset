# 遇到的問題與處理方式（簡報第 11 頁改寫素材）

本文件整理專題實作過程中**真實遇到且有實際處理**的核心問題，避免過度包裝或與實驗數據矛盾。

---

## 問題一：路面標線（斑馬線、機車待轉區）因透視呈梯形，矩形框易混入背景

- **問題現象**：  
  行車記錄器為前視透視角度，地面的斑馬線與機車待轉區在畫面中多呈現**扁平梯形**；但 YOLOv7 採用水平矩形框（HBB），被迫以矩形去包覆梯形，導致框內混入左右兩側大量柏油路背景，且目標長寬比極端扁平，容易造成 Anchor 匹配失敗或定位偏差。
- **處理方式**：
  1. **標註端統一規範**：全組採用「最小緊貼外接矩形」框住標線四個極端點，遇車輛局部遮蔽仍視為同一完整目標，減少標註雜訊。
  2. **訓練端超參數適配（v1）**：將 **`anchor_t` 由 `4.0` 放寬至 `6.0`**，容許極扁長寬比目標匹配 Anchor；同時**關閉旋轉（`degrees=0`）、剪切（`shear=0`）與透視變形（`perspective=0`）**，避免水平框進一步膨脹失真。

## 問題二：純人工標註耗時高，委託通用 AI Agent 代標卻出現框體漂移、誤標與漏標

- **問題現象**：  
  行車記錄器影片雖可透過抽幀工具快速產出大量影像，但純人工精標 **50 張即需耗時約 1～1.5 小時**；若改請通用 AI Agent 參考人工範例直接代為標註，實測發現容易出現**邊界框位置漂移、類別標錯或漏標**（通用視覺語言模型對精確像素座標回歸較弱，且缺乏台灣特有「機車待轉區」與細分標誌概念）。
- **處理方式與建議解法（Human-in-the-Loop 人機協作）**：
  1. **嚴格人工複檢**：不直接將通用 AI Agent 的輸出送入訓練，改以 X-AnyLabeling 逐張修正，避免錯誤標籤污染模型（Garbage In, Garbage Out）。
  2. **專屬模型預標註（Model-Assisted Pre-labeling）**：先以人工精標的種子資料（如現有 458 張）訓練出**專屬 YOLOv7 模型**（如 Exp 7 / Exp 8），再對新抽幀影像執行推論產生**初始預標註框**，匯入 X-AnyLabeling 後由人工只做**「微調與補漏」**而非從零畫框，可大幅降低漂移並將標註速度提升數倍。
  3. **信心度分流審核**：預標註時保留信心分數，高信心目標快速掃描確認、中低信心目標優先人工複查，將時間集中在模型最不確定的難例上。
